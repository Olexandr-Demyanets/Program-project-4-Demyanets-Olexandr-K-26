# Програмний проєкт 4 - варіант 5

Структура даних `ThreeFields` для багатопотокової програми: m = 3 цілих полів, `get`/`set` для кожного поля
і `operator std::string` для всієї структури.
Частоти операцій: поле 0 - read 9 %, write 1 %; поле 1 - read 40 %, write 10 %; поле 2 - read 10 %, write 10 %;
string - 20 %. Захист даних - один `std::mutex` на всю структуру.

## Вимоги

- компілятор з підтримкою C++20 (перевірено на g++ 15.2.0, MSYS2 UCRT64);
- CMake 3.20+.

## Збирання

З папки проєкту:

```
cmake -S . -B build -G "MinGW Makefiles"
```

`cmake --build build`
Без CMake:

```
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic src/generator.cpp -o generator.exe
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic src/main.cpp -o benchmark.exe
```

## Запуск

Згенерувати тестові файли (18 файлів у `tests/`):

```
build\generator.exe
```

Виміряти час:

```
build\benchmark.exe
```

Записати вивід у файл:

```
build\benchmark.exe > results.txt
```

Порівняти з альтернативними схемами захисту:

build\benchmark.exe --compare > compare_results.txt
buildbenchmark.exe --compare > compare_results.txt
```

Необов'язкові аргументи: `generator [каталог] [операцій] [seed]`, `benchmark [каталог] [запусків]`,
`benchmark --compare [каталог] [запусків]`.

## Як це працює

- `get`/`set` блокують м'ютекс на час читання/запису одного поля; `operator string` під м'ютексом лише копіює
  три значення, а рядок форматує після розблокування. Кожна операція тримає один м'ютекс, тож взаємоблокування неможливе.
- Чому один м'ютекс: string (20 %) потребує всіх полів одразу; поле 1 задіяне у 70 % операцій, тож розділення
  м'ютексів майже не дає паралельності; `std::shared_mutex` у MinGW у 4-5 разів повільніший, може зависнути
  при одночасному першому блокуванні і не звільняє пам'ять.
- `generator` для кожного сценарію і кожної кількості потоків t = 1, 2, 3 створює t файлів по 1 200 000 / t операцій
  (`<сценарій>_t<потоків>_<номер>.txt`); частоти точні, порядок випадковий (`std::mt19937_64`, seed 2026).
- `benchmark` спершу зчитує всі файли, потім потоки чекають на спільний старт (`std::mutex` + `std::condition_variable`),
  тож у час не входять ні зчитування файлів, ні створення потоків. 1 прогрівальний і 10 виміряних запусків.

| Сценарій | read0 | write0 | read1 | write1 | read2 | write2 | string |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| а) як в умові | 9 | 1 | 40 | 10 | 10 | 10 | 20 |
| б) усі рівні | 14.29 | 14.29 | 14.29 | 14.29 | 14.28 | 14.28 | 14.28 |
| в) далекі від умови | 1 | 40 | 2 | 5 | 2 | 45 | 5 |

Порівняння схем на файлах а) (мс, `benchmark --compare`):

| Схема | 1 потік | 2 потоки | 3 потоки |
| --- | ---: | ---: | ---: |
| 1 `std::mutex` (обрано) | 15.07 | 27.94 | 28.39 |
| 2 `std::mutex`: {1}, {0, 2} | 17.15 | 32.98 | 34.56 |
| 3 `std::mutex` | 19.25 | 38.12 | 42.20 |
| 1 `std::shared_mutex` | 57.51 | 132.34 | 141.30 |
| 3 `std::shared_mutex` | 78.37 | 213.85 | 229.38 |

## Файли

- `src/three_fields.h` - структура даних;
- `src/generator.cpp` - генератор тестових файлів;
- `src/main.cpp` - зчитування файлів, виконання в потоках, вимірювання часу для таблиці 3×3 і порівняння схем захисту (`--compare`);
- `CMakeLists.txt` - збирання;
- `results.txt`, `compare_results.txt` - вивід програм;
- `report.docx` - звіт.
